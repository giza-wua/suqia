# شرح قاعدة البيانات (schema.sql)

`schema.sql` نفسه من غير أي تعليقات عمداً (عشان ينفَّذ يدوياً من كونسول Cloudflare D1 من غير مشاكل تقسيم). الشرح الكامل لكل جدول وعمود موجود هنا بدل ما يكون تعليقات جوه الملف.

## ملاحظة معمارية عامة

قاعدة البيانات دي بديل لـ Firestore (اللي كان التطبيق شغّال بيه الأول). الفرق الجوهري: Firestore بلا شكل ثابت (schemaless) — أي مستند ممكن يكون فيه حقول مختلفة. D1 قاعدة علائقية (SQLite)، فكل جدول له أعمدة ثابتة. القرارات المعمارية الرئيسية:

- **لا يوجد `login_index`/`login_index_phone`:** في Firestore، البحث عن مستخدم باسم المستخدم كان محتاج جدول فهرسة منفصل لأن Firestore مايدعمش استعلام مرن على أي حقل. في D1، عمود `username` نفسه معمول عليه `UNIQUE`، فالبحث `WHERE username = ?` مباشر وسريع من غير أي جدول إضافي.
- **`canal_history` جدول مستقل مش subcollection:** كان في Firestore عبارة عن subcollection تحت كل مستند ترعة. في D1، بقى جدول مستقل فيه عمود `canal_id` بيربطه بالترعة عبر `FOREIGN KEY` — يعني لو اتحذفت الترعة، سجل تطهيرها بيتحذف تلقائياً معاها (`ON DELETE CASCADE`).
- **كل الجداول فيها `id TEXT PRIMARY KEY`:** مش رقم تلقائي (`AUTOINCREMENT`) عشان الـ IDs المتولّدة من الكود (UUID) تفضل ثابتة حتى لو استعدت نسخة احتياطية قديمة على نفس السجلات (upsert بنفس الـ id).

## `users` — فريق العمل (المستخدمين اللي بيسجّلوا دخول)

| العمود | النوع | الشرح |
|---|---|---|
| `id` | TEXT (PK) | معرّف فريد (UUID) |
| `username` | TEXT UNIQUE | اسم المستخدم، وهو طريقة الدخول الوحيدة (بعد قرار 1.0.9) |
| `phone` | TEXT UNIQUE | رقم موبايل، بيانات تواصل فقط — مش وسيلة دخول |
| `email` | TEXT | بريد حقيقي، أو بريد داخلي وهمي (`username@internal.zimam`) لو المستخدم مالوش بريد |
| `has_real_email` | INTEGER (0/1) | هل البريد حقيقي ولا وهمي؟ بيتحكم في تحذير "معندكش بريد استرداد" في صفحة الفريق |
| `password_hash` / `password_salt` | TEXT | كلمة المرور مشفَّرة بـ PBKDF2-SHA256 (600 ألف تكرار)، مش نص صريح أبداً |
| `display_name` | TEXT | الاسم اللي بيظهر في الواجهة |
| `role` | TEXT | واحدة من: `admin` (مدير عام، كل الصلاحيات)، `editor` (مدخل بيانات، يقدر يضيف/يعدّل/يحذف)، `viewer` (مشاهدة فقط) |
| `created_at` | TEXT | تاريخ إنشاء الحساب |

## `masaqi` — المساقي

| العمود | الشرح |
|---|---|
| `name` | اسم المسقى |
| `directorate` | الهندسة المسؤولة |
| `village` | القرية |
| `canal` | الترعة المغذية (نص حر، مش FK) |
| `status` | `تحتاج للتطهير` / `قيد العمل` / `تم التطهير` |
| `gps` | إحداثيات نصية (لينك جوجل مابس) |
| `date` | تاريخ آخر تطهير |
| `zamam` | المساحة المنتفعة (فدان) |
| `length` | طول المسقى (متر) |

## `canals` — الترع

| العمود | الشرح |
|---|---|
| `feeder_canal` | اسم الترعة أو المصدر اللي بيغذّي الترعة دي |
| `bank` | البر (يمين/يسار) |
| `command_area` | الزمام — المساحة اللي بتتغذى من الترعة (فدان) |
| `discharge_rate` | التصرف المائي (م³/ث أو الوحدة المعتمدة محلياً) |
| `sections_json` | نص JSON لمصفوفة المقاطع الهندسية للترعة (من كم لكم، عرض القاع، الميول، منسوب المياه، المناوبة...) — مخزَّن كنص لأن SQLite مالهاش نوع "مصفوفة" أصلي |
| `is_lined` | 0 أو 1 — هل الترعة مبطنة؟ |
| `lining_type` / `lined_length` | نوع التبطين وطوله، لو مبطنة |
| `next_scheduled_date` / `last_dredging_date` | الموعد القادم للتطهير، وتاريخ آخر تطهير فعلي |

## `canal_history` — سجل أعمال تطهير كل ترعة

| العمود | الشرح |
|---|---|
| `canal_id` | مفتاح أجنبي على `canals.id`، بيتحذف تلقائياً لو اتحذفت الترعة |
| `status_after` | الحالة بعد الحدث المسجَّل (نفس قيم `canals.status`) |
| `recorded_by` | اسم اللي سجّل الحدث |

## `bridges` — الكباري

`bridge_type` (نوع الكوبري: سيارات/مشاة...)، `canal_name` (الترعة أو المصرف اللي عليه الكوبري)، `span` (الامتداد)، `load` (الحمولة القصوى)، `material` (الخامة)، `build_year`، `condition` (الحالة الإنشائية).

## `wells` — الآبار

`purpose` (الغرض: ري حكومة/خاص...)، `water_level` (منسوب المياه)، `design_capacity`/`actual_capacity` (الطاقة التصميمية والفعلية)، `pump_type`/`pump_power` (نوع وقدرة الطلمبة)، `drill_year` (سنة الحفر).

## `drains` — المصارف

`eng` (الهندسة المسؤولة — إجباري)، `canal_name` (الترعة القريبة)، `zomam` (المساحة المخدومة).

## `members` — أعضاء رابطة مستخدمي المياه

`national_id` (الرقم القومي، اختياري)، `masqa` (المسقى اللي العضو تابع له)، `holding` (الحيازة بالفدان).

## `news` — الأخبار

`type`: `عام` / `عاجل` / `توعية`. `date_string` نص عرض ثابت (بيتحدد وقت الإنشاء ومايتغيّرش عند التعديل).

## `tickets` — البلاغات الميدانية

الجدول الوحيد اللي أي حد (حتى بدون تسجيل دخول) يقدر يكتب فيه — البلاغ من موقع عام. `status` الافتراضية `جديد`، وبعدين تتغيّر لـ `قيد المتابعة` أو `تم الحسم` من فريق العمل.

## `activity_log` — سجل الأنشطة

بيتسجَّل تلقائياً من كود الـ Worker نفسه مع كل عملية إضافة/تعديل/حذف — مش من الكلاينت (كان كذلك في التصميم الأصلي بـ Firestore، اتغيَّر لأمان أعلى: العملية والتسجيل بيحصلوا سوا في نفس الطلب).
